# nixos-installer

A lightweight, friendly NixOS installer. Boot the ISO, answer a few questions, and get a plain NixOS. It can then hand over to your dotfiles.

It owns the machine layer: partitions, encryption, swap, hibernate, hardware configuration, bootloader, hostname and timezone. It writes these to `/etc/nixos` and knows nothing about your personal setup. Sizes come from what it detects, and every suggestion can be edited.

**It erases the disk you choose.** Dual boot isn't supported. Nothing is changed until you type the disk's name at the final confirmation.

## Build and flash

Set your default dotfiles repo and branch in `settings.nix`. You can also change them at install time, or leave the repo empty to stop at plain NixOS.

**1. Build the ISO** for the architecture you're on:

```bash
nix build .#iso
ISO=$(echo result/iso/*.iso)
```

**2. Find the USB stick.** Plug it in and look for the `disk` row with `usb` under `TRAN`, such as `sdb`. Check its size and model: the next step erases whatever device you name, without asking. Use the whole disk (`sdb`), not a partition (`sdb1`).

```bash
lsblk -o NAME,SIZE,TYPE,TRAN,MODEL,MOUNTPOINTS
```

**3. Write the ISO and check the copy.** Replace `sdX` with the stick's name. If `lsblk` shows any of its partitions mounted, unmount each one first with `sudo umount /dev/sdX1`.

```bash
sudo dd if="$ISO" of=/dev/sdX bs=4M status=progress conv=fsync
sudo cmp -n "$(stat -Lc %s "$ISO")" "$ISO" /dev/sdX && echo VERIFIED
```

**4. Boot from it.** Once you see `VERIFIED`, take the stick out and plug it into the new machine. Disable Secure Boot in the firmware, then choose the stick from the firmware's boot menu.

Rebuild and reflash after changing `install.sh`, `first-boot.sh`, `iso.nix` or `settings.nix`. Changes to your dotfiles don't need it, because they're cloned at first boot.

## What it writes

| File in `/etc/nixos` | Purpose |
|---|---|
| `hardware-configuration.nix` | Generated by `nixos-generate-config`: drivers, disks, CPU architecture |
| `machine.nix` | Your answers, and the build limits calculated from RAM and CPU threads |
| `configuration.nix` | Imports those two and adds a user, network, git, age, sops and flakes |
| `dotfiles-source`, `first-boot.sh` | Only if you chose a dotfiles repo |

## Dotfiles contract

A dotfiles repo needs to be readable without logging in and to provide `nixos/bootstrap.sh`. On the first login on tty1, the system clones the repo to `~/dotfiles` and runs that script. If it fails, you keep a working NixOS and can retry with `bash /etc/nixos/first-boot.sh`.

If the repo also has `nixos/secrets/template.yaml`, a list of `name: null` lines, the same step gives the machine its own secrets before running the script:

- `~/.config/sops/age/keys.txt`: a new age key.
- `~/.config/sops/secrets.yaml`: the template, encrypted to that key.

Both files stay on the machine, and a re-run never replaces them. Fill in the values with `sops edit ~/.config/sops/secrets.yaml`.

To use the machine layer from a flake, import `/etc/nixos/hardware-configuration.nix` and `/etc/nixos/machine.nix`, and rebuild with `--impure`.

## Tests

```bash
bash tests/test-install.sh                # unit tests, no disks involved
VM_TEST_WORK=/some/dir tests/vm-test.sh   # full installs in throwaway QEMU VMs
```

The VM tests write only to qcow2 images in the work directory. They download a few GiB per install and use 2.5 GiB of RAM per VM.
